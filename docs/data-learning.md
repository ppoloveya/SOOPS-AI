# 고객 데이터 학습 구조

앱에서 기록한 내용이 서버로 모여, 고객별 맞춤과 고객 전체 학습으로 정확도가 쌓이는 구조다. **코드와 마이그레이션 파일만 추가했고, 어떤 서버에도 적용하거나 배포하지 않았다.** 아래 체크리스트를 끝내기 전에는 운영에 올리지 말 것.

## 흐름

```
앱(기기 저장이 기준) ─ 선택 동의한 고객만 ─▶ skin_diary_logs (익명 계정, 하루 1행)
                                                │
                       scripts/learn-priors.mjs (서버에서 정기 실행)
                                                ▼
                          population_priors (요인별 평균·산포, 30명 이상일 때만)
                                                │
앱 리포트 ◀──── estimateDifference(개인 기록, 사전 분포) ────┘
```

- 기록이 적은 새 고객: 사전 분포(고객 전체에서 학습한 값)에서 출발한다. 고객이 늘수록 이 출발점이 좋아진다.
- 기록이 쌓인 고객: 개인 관측값이 우선한다. 개인 기록이 많을수록 고객 전체 값의 영향은 줄어든다.
- 모델은 LLM이 아니라 통계 모델(랜덤효과 메타분석 + 베이지안 갱신)이다. 건강 일기를 생성형 AI에 학습시키지 않는다.

## 서버로 보내는 것 / 보내지 않는 것

- 보냄: 날짜, 피부 타입, 민감도, 선택한 고민, 고민별 점수, 앰플 사용 여부, 수면 분, 감정 태그, 운동 종류, 생활 요인(생리 전·중 포함)
- 보내지 않음: 자유 입력 메모, 식물 이름, 기기·위치 정보. `src/lib/solvera/cloud.ts`의 `toCloudRow`가 유일한 전송 형태이고 테스트로 막아 두었다.
- 계정: 로그인 없이 Supabase 익명 계정을 쓴다. 이름·이메일은 받지 않는다. 쿠폰 신청용 인스타그램 DM 정보와는 연결하지 않는다.

## 적용 전 체크리스트

1. **법적 확인(필수).** 생리 주기·피부 상태는 건강 관련 정보이고 개인정보 보호법상 민감정보로 볼 수 있다. 별도 동의, 수집 항목·목적·보유기간 고지, 해외 서버 이전 여부(Supabase 리전) 확인이 필요하다. 동의 문구(`Consent` 화면)는 초안이므로 법률 검토 후 확정하고, 바꾸면 `CONSENT_VERSION`을 올려 다시 동의받는다.
2. **보유기간 정하기.** 현재는 철회·초기화 때만 삭제된다. 정기 삭제 정책이 필요하다.
3. **Supabase 설정.** 대시보드에서 *Anonymous sign-ins*를 켠다.
4. **마이그레이션 적용.** `supabase/migrations/20261128000000_skin_diary_learning.sql`을 검토한 뒤 적용한다. 새 테이블은 모두 RLS가 켜져 있고, 본인 행만 읽고 쓰며, 동의를 철회하면 쓰기가 막힌다.
5. **학습 스크립트 예약 실행.** 서버에서만, 서비스 롤 키를 비밀값으로 두고 실행한다. 처음에는 `node scripts/learn-priors.mjs --dry-run`으로 결과를 확인한다.
6. **관찰 지표 정하기.** 정확도가 실제로 좋아지는지 보려면 "다음 주 점수를 기록 전에 예측해 보고 실제와 비교"하는 식의 평가가 필요하다. 지금은 구현하지 않았다.

## 알아둘 점

- 사전 분포는 사용자 30명 미만이면 만들지 않는다(`MIN_USERS_FOR_PRIOR`). 초기에는 학습 효과가 없고 기본값(평균 0)으로 동작한다.
- 학습 결과가 곧 "원인"은 아니다. 고객 전체에서 같은 방향이 나와도 자가 기록의 연관성이다.
- 사전 분포가 좋아져도 리포트의 "원인·제품 효과 판정 아님" 문구는 유지한다.

## 사용 흐름 측정과 친구 응원 (`20261128000100_events_and_gifts.sql`)

- **측정:** `app_open`, `first_log`, `challenge_complete`, `next_cycle_start`, `share_click`, `share_link_open`, `gift_sent` 7가지 사건과 기기별 임의 ID만 저장한다. 피부·건강 기록, 메모, 식물 이름은 보내지 않는다. 브라우저의 "추적 안 함"이 켜져 있으면 보내지 않는다. 퍼널은 서비스 롤로 `select * from app_funnel`을 조회한다.
- **응원:** 공유 링크의 임의 토큰으로만 식물을 가리키고, 계정·이름·건강 정보와 연결하지 않는다. 한 식물이 하루에 받을 수 있는 응원은 10개까지이고, 보낸 사람은 저장하지 않는다. 응원은 경험치에 더해지지 않는다.
- **적용 전 확인:** 측정도 개인정보 처리방침에 한 줄 고지가 필요하다. 이 마이그레이션도 아직 어떤 DB에도 적용하지 않았다.

## 대화형 기록의 데이터 신뢰도

- **출처 표시:** 기록의 수면·기분·운동·생활·앰플 항목은 "직접 입력·확인(user)" 또는 "말하지 않아 기본값(default)"으로 저장된다. 기본값 항목은 생활 요인 비교, 재발 예측, 앰플 사용 비율에서 제외한다. 출처가 없는 이전 기록과 일반 폼 기록은 직접 입력으로 본다.
- **확인 카드:** 대화형에서 문장을 읽은 뒤 칩으로 보여주고 틀린 곳만 고치게 한다. 말하지 않은 항목은 "비워둠"으로 두며, 고객이 누르면 직접 입력이 된다.
- **읽기 규칙:** "6시간 잤어"처럼 정확한 수면 시간을 읽고, "스트레스 안 받았어", "술 안 마셨어" 같은 부정문은 해당 항목으로 읽지 않는다.
- **측정:** `chat_parse_confirmed`(고치지 않고 확인), `chat_parse_corrected`(고침). 두 값의 비율이 대화형 해석의 정확도 지표다. 이 값이 높게 고쳐진다면 읽기 규칙을 더 손봐야 한다는 신호다.
- **한계:** 예측 엔진은 기본값 항목을 "해당 없음(0)"으로 두고 학습한다. 기록이 듬성듬성해지면 예측 검증이 더 어려워진다.
